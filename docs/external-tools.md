# 外部服务

## Open-Meteo 天气

无需在本机实验中填写天气 Key。2026-09-22 主机及 Docker 均取得杭州浙江的真实预报，城市 ID 1808926，状态 ok。生产/商业用途需自行确认供应商授权和额度。

- 同名城市返回候选，用户确认后提交 weather_location_id；不猜坐标。
- 状态为 ok、partial、out_of_range、ambiguous、unavailable。
- 单次请求超时 8 秒，整条天气查询上限 18 秒，失败不阻塞模型规划。
- 只传递 days 覆盖的日期，降雨概率至少 60% 时建议室内。
- 来源、查询时间随方案保存；历史不是自动更新的实时预报。
- WEATHER_ENABLED=false 停止自动生成前查询，用户主动查询接口仍可使用。
- WEATHER_TRUST_ENV=false 默认绕过环境代理。本机此前代理配置导致连接失败，直连已成功。

## Dify 与知识库

已发布规划节点的 context 绑定检索 result，提示词引用 context。真实广州生成返回 5 条检索来源，界面可展开资料名和片段。来源只证明检索链路返回资料，不证明每条行程事实正确。

DSL 导入新环境需要重新配置模型和知识库。模型凭证留在 Dify，旅行 API 的应用 Key 仅保存在本机 .env。知识库以广州样例为主，更多目的地需要扩充有来源资料。

## 地图与路线

地图按钮打开地点搜索；结构化日程可调用 Nominatim 解析地点，再由 OSRM driving 接口估算道路距离和时间。此结果不是实时公交、步行或拥堵数据；服务不可用时明确提示，不补造耗时。公开演示服务有使用限制，规模化部署应配置自有服务或合适的供应商。

车票、酒店库存和预订未接入。闭馆检查仅识别方案中的提示文本，不会查询场馆实时状态；局部调整将规则建议写入行程供用户确认。
