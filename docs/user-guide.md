# 行旅使用与维护

## 本机运行
安装 Python 3.9+，双击“启动工作台.cmd”；第一次联网安装 requirements.txt。打开 8790 端口。窗口中 Ctrl+C 正常停止。需要更换端口时设置 TRAVEL_PORT。账号与历史位于 data/travel.db。

## 两种规划方式
没有 Dify Key：生成可编辑的手动日程框架，所有尚未核实的信息明确待确认，不虚构 AI 输出。
已配置 Dify：先确保 Dify 和模型服务运行，在 .env 填写应用 Key 与 URL，再重启。/api/ready 表示本地配置与存储就绪，并不证明上游模型每次都可用。

## 一次完整旅行
1. 输入日期、预算、人数与偏好。预算为所有同行者合计。
2. 可先查询天气、确认同名城市。查询超出预报时间或服务失败时，照常创建方案并提示原因。
3. 生成过程中查看状态与正文；中断或失败的半成品不会进入历史。
4. 展开每日编辑器，添加/删除活动并修改字段，点击保存。
5. 对照地图、预约与实际票价人工确认。路线仅为驾车估算，不含实时路况。
6. 下载 Markdown / 日历，或浏览器打印选择“另存为 PDF”。导出取保存后的日程，原始模型文本单独保留。
7. 修改整体需求时使用修订入口，新结果保留父版本关联。注册账号后可检索历史及保存偏好。

## 故障排查
- 只出现手动模式：检查本机 .env 是否填写 DIFY_API_KEY，修改后重启。
- 已配置但生成失败：检查 Dify 服务、应用是否已发布、模型额度、应用模式和网络；不要把 Key 发到 Issue。
- 请求频率过高：默认每 IP 每小时 20 次生成，最多同时处理 4 个生成；稍后重试，历史与编辑仍可用。
- 天气/地图不可用：查看来源提示，核实网络与外部服务状态；手动编辑和历史不依赖这些接口。
- 账号之间切换：已保存内容留在所属账号；登录/退出会清理当前页面的私人内容。

## 备份与调试
停服后备份 data 和本机 .env；恢复时停服，按原版本恢复。Docker 数据保存在 travel-data 卷，不要执行会删除该卷的命令。

从 api/main.py 的 create_stream 入口读起，在 streaming.py 看 SSE，history.py 看 SQLite。可用 `python -m uvicorn api.main:app --reload --port 8790` 调试，/docs 提供接口试用。测试自动禁用真实 Dify，避免误产生模型调用费用。生产使用不启用 --reload。
